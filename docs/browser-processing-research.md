# Browser crop/rotation research and processing modules

2026-10-11. Source inspection only: no downloaded code was executed, no browser/scanner was accessed, and no scan was processed. References were downloaded under ignored `references/`.

Implementation follow-up: the standalone app now has a modular ScannerDriver registry and local processing modules under `web-app/src/processing/`, including conservative crop/render workers and the pinned local Tesseract OSD adapter. See [modular driver and processing documentation](modular-driver-processing.md) for the implementation contract, preserved originals, limits, undo/export behavior and public-host worker headers. The comparisons below remain research evidence; they do not claim the referenced third-party scanners were run on this hardware.

**Recommendation:** keep the direct TypeScript driver and add a bounded, reversible worker pipeline for border cropping and explicit rotation. This is sufficient for conservative ADF border removal and manual 90/180/270 rotation; it is **not** sufficient to promise that arbitrary text is automatically upright. Treat text/content cropping and OCR orientation as separate opt-in processors.

## Separate three kinds of rotation

1. **Explicit quarter turns:** user-selected 90/180/270; exact pixel geometry can be transformed without estimating content. Keep original JPEG bytes, because canvas export decodes/re-encodes rather than performing a lossless JPEG-domain rotation.
2. **Line direction and small deskew:** text projections or component geometry can suggest horizontal versus vertical lines and a small tilt. Reversing a page by 180° preserves the line direction, so such a detector cannot prove upright versus upside-down. Portrait dimensions alone also do not prove orientation. Mixed layouts, tables, photos and vertical scripts must allow an uncertain/no-op result.
3. **Upright text 0/90/180/270:** optional OCR orientation detection. [Tesseract.js API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md#workerdetectimage-jobid-promise) requires `legacyCore: true` and `legacyLang: true` for worker.detect; this is disabled by default. Its [worker implementation](https://github.com/naptha/tesseract.js/blob/master/src/worker-script/index.js#L411) returns orientation degrees/confidence or nulls when detection fails. Conversely, recognize's rotateAuto at lines 343–378 uses FindLines/GetGradient: it is deskew, not a replacement for OSD. [Tesseract OSD source](https://github.com/tesseract-ocr/tesseract/blob/main/src/ccmain/osdetect.cpp#L247) skips pages with too few usable text blobs and compares four character orientations. Photos, blank backs, sparse labels and mixed scripts are not reliable OSD inputs. Calibrate a confidence threshold against representative scans; confidence is not a universal probability. Test clockwise/counterclockwise conventions on known 90/270 fixtures before applying detected angles.

## Conservative initial pipeline

- Keep immutable original bytes and a reversible transform record. Produce a distinct processed result, with Reset to original and a preview of what would be removed. No processor overwrites the original or silently deletes a blank side.
- Define default crop as **uniform outer border removal**, using a bounded downscaled sample and per-edge background/variance estimates. Require a continuous plausible border with agreement across multiple rows/columns; reject conflicting, tiny or excessive rectangles. Map bounds back with outward rounding and padding. A cap on each edge's trim and total retained area is a guard, not proof that content is safe.
- Keep **content crop** opt-in: ink bounds can legitimately remove blank margins that the user wants retained. Preserve edge-touching foreground, faint pencil, light colors, stamps and small isolated marks unless explicitly filtered. Blank/low-confidence/full-bleed/photo/irregular results should leave the page unchanged. Threshold sensitivity and scanner background color need fixtures before claims of accuracy.
- Decode in a worker with createImageBitmap(Blob); analyse only bounded pixels; rotate/crop once at full output resolution using OffscreenCanvas. [The HTML standard](https://html.spec.whatwg.org/multipage/canvas.html#the-offscreencanvas-interface) defines canvas rotation and async convertToBlob, with PNG fallback if an encoding is unsupported. Feature-detect worker canvas support, cap decoded/output pixel counts, serialize jobs, support cancellation and close owned ImageBitmaps. Expand arbitrary-angle output bounds and fill exposed areas; rotating inside the old dimensions clips corners.
- Run crop/orientation suggestions independently, then apply the accepted transform chain once. Store crop coordinate frame, source dimensions, analysis scale, rotation, processor version and confidence/reason. Separate original and processed exports so processing failures do not discard a completed scan.

## Modules and dependencies

Keep scanner drivers responsible for discovery, reported capabilities, device options, acquisition, page-side identity and session cleanup. Give processing plugins a device-independent PageAsset plus settings, AbortSignal and bounded resource budget; return a transform proposal/result and reason. Hardware CRP/PEDT and software border crop must have different settings/provenance. Do not advertise a hardware feature simply because a host processor can imitate part of it.

Native Canvas/typed-array analysis is a reasonable first dependency-free implementation for uniform borders. Lazy-load official OpenCV.js if connected-component morphology, variable backgrounds or camera quadrilaterals become necessary; delete every owned Mat/MatVector even on error. Lazy-load Tesseract.js only when true upright text detection is requested, with pinned/cached worker/core/language assets and a manual fallback. DBNet/ONNX dewarp is not justified for ordinary flat ADF pages until simpler detection demonstrably fails. Retain MIT/Apache notices and source pins for any code actually copied; no implementation code was copied during this investigation.

## Concrete local Tesseract OSD adapter (follow-up)

Inspected official npm tarballs without executing them: [tesseract.js 7.0.0](https://registry.npmjs.org/tesseract.js/7.0.0), [tesseract.js-core 7.0.0](https://registry.npmjs.org/tesseract.js-core/7.0.0), and [@tesseract.js-data/osd 1.0.0](https://registry.npmjs.org/@tesseract.js-data/osd/1.0.0). Pin core 7 explicitly: its registry `latest` tag currently points to 6.1.2 despite 7.0.0 being available and required by wrapper 7.0.0. Wrapper source commit is `42eae669e4b3a66429d8516f078912cc747a89df`; osd package source is `b86746569320a6103cea84cc2b8d9ee74f0f45d3` in naptha/tessdata.

Use `createWorker('osd', OEM.TESSERACT_ONLY, {legacyCore: true, legacyLang: true, workerBlobURL: false, workerPath, corePath, langPath, gzip: true, cacheMethod: 'write'})`, with all three paths explicitly absolute and same-origin. OEM.TESSERACT_ONLY is 0. The data package's own index.js selects **4.0.0**, not 4.0.0_best_int. Copy `4.0.0/osd.traineddata.gz` to the local lang directory; its SHA-256 is `d1c9e6aad4f23167d0bb88a35e496596774b536cf85c190d3a0fa5cab48bbdfd` and size 4,320,198 bytes. No English data is needed for an OSD-only worker.

Copy worker.min.js and the three non-LSTM core loader variants: `tesseract-core.wasm.js`, `tesseract-core-simd.wasm.js`, and `tesseract-core-relaxedsimd.wasm.js`. [Core selection source](https://github.com/naptha/tesseract.js/blob/42eae669e4b3a66429d8516f078912cc747a89df/src/worker-script/browser/getCore.js) chooses among them according to feature detection. In the inspected core 7 tarball, these `.wasm.js` files embed WASM; separate raw `.wasm` files are not needed by this loader. Copying all six loader variants is reasonable if later enabling LSTM OCR; an OSD-only adapter does not select the LSTM variants.

**Rotation sign is already corrected in Tesseract.js.** Its [detect source](https://github.com/naptha/tesseract.js/blob/42eae669e4b3a66429d8516f078912cc747a89df/src/worker-script/index.js#L446) maps orientation_id through `[0,270,180,90]` before returning orientation_degrees. That matches [Tesseract's OrientationIdToValue](https://github.com/tesseract-ocr/tesseract/blob/main/src/ccmain/osdetect.cpp#L520), the clockwise rotation needed to make text upright. Therefore apply JS orientation_degrees directly as a clockwise canvas rotation: physically CW90 text should return 270 correction; CW270 returns 90; upside-down returns 180. **Do not negate it a second time.** Raw C++ DetectOrientationScript instead returns id×90, explaining conflicting CLI/API examples.

Start with confidence ≥15, the [official API's reasonably-confident value](https://github.com/tesseract-ocr/tesseract/blob/main/src/api/baseapi.cpp#L1538); it is a margin score rather than a probability. Accept only finite confidence and one of 0/90/180/270; nulls, failures, cancellation, timeouts and low confidence mean leave orientation unchanged. Serialize detect calls on a lazy reused worker; terminate/recreate after timeout instead of leaving unresolved jobs. Feed local encoded image bytes (Uint8Array) rather than URL strings, so image loading needs no HTTP request. Detect an unmodified analysis copy, and compose the accepted correction with user rotation explicitly; OSD must not silently reset manual crop/rotation state.

An external worker needs its own delivered CSP, not just assumptions about the page's policy. For static same-origin assets, permit script execution from the local asset directory and WASM compilation (`wasm-unsafe-eval`), but never JavaScript unsafe-eval/CDN origins. Worker connect-src can allow only the exact local language asset URL/path; it need not allow image endpoints or arbitrary external networking when detect receives bytes. Use an allowlist fetch wrapper as additional defense where hosting cannot set worker-response CSP, and retain the processing worker's no-network policy separately. Model cache stores traineddata, not scan pixels; cacheMethod 'none' is also supported if caching is unwanted.

Wrapper/core packages carry Apache-2.0. The osd npm wrapper metadata says MIT, but [naptha/tessdata LICENSE](https://github.com/naptha/tessdata/blob/gh-pages/LICENSE) and its [upstream tessdata source](https://github.com/tesseract-ocr/tessdata/blob/main/LICENSE) carry Apache-2.0. Retain both recorded package provenance and the upstream Apache text for the redistributed traineddata; do not label the model solely MIT based on wrapper metadata.
